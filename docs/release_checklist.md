# 发布检查清单（DEP-09）

每项必须填写“通过/不适用（理由）/阻断”，不得用单元测试替代服务器演练证据。

## 发布前

- [ ] 固定候选SHA、RC Tag、Web镜像摘要和基础镜像版本。
- [ ] Repository policy、Ubuntu、Windows、容器CI和漏洞扫描通过。
- [ ] 不存在未接受的P0/P1缺陷；HIGH漏洞已有负责人和到期日。
- [ ] 云资产、固定公网IPv4、安全组、SSH来源、COS及责任人已登记。
- [ ] 80端口只允许校园网、VPN或明确可信来源；443、8000和数据库端口未开放。
- [ ] 真实数据授权、隐私告知、访问范围和保存期限已审批。
- [ ] 数据库、媒体和配置键名清单已备份，COS对象版本及SHA-256已记录。
- [ ] 回退镜像、恢复备份、维护窗口、执行人和复核人已确认。

## 发布中

- [ ] `docker compose config --quiet`通过，镜像摘要与审批一致。
- [ ] 写入已暂停；迁移、启动和九支部初始化结果已记录。
- [ ] Web与Nginx healthy；仅Nginx 80端口按白名单开放，8000未发布。
- [ ] `http://<FIXED_PUBLIC_IPV4>` 健康端点和静态资源正常。
- [ ] 登录、查询、导入历史和审计日志通过脱敏抽查。

## 发布后

- [ ] 宿主机和Compose重启后数据与健康状态正常。
- [ ] 首次发布后备份上传COS并完成校验。
- [ ] 磁盘、时间同步、HTTP健康和备份新鲜度监控正常。
- [ ] 版本、镜像摘要、备份、操作时间、执行人、复核人和缺陷已归档。
- [ ] 项目、运维、数据和安全负责人完成Go签字。

任一必选项阻断时停止发布，不创建正式Tag、不导入真实数据、不开放公网。
