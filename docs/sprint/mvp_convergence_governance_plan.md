## 6. 模块作业边界

### 管理员模块

负责管理员认证、统一权限工具、学生列表/筛选/分页/详情和审计服务；不得进入`apps/imports`实现Excel业务，不得修改学生认证契约。

### Excel解析器

唯一入口保持为`apps.imports.parser.parse_workbook(Path) -> ParseResult`。解析器只读文件并返回规范化结果，不保存上传、不写数据库、不实现预览、导入或回滚。

### Excel导入模块

只消费管理员权限、审计服务和生产解析器；不得复制角色判断或解析逻辑，不得从客户端重建可信ParseResult，不得修改思想汇报唯一约束。

## 7. PR 1：上传、服务端预览与历史

实现原始文件保存、文件哈希、生产解析器调用、服务端`preview.json`及SHA-256、空结果预览、错误警告展示、导入历史和受控下载。预览阶段不得写Student及材料业务表。

建议批次目录：

```text
media/imports/batch_<id>/
├── original.xlsx
├── preview.json
└── preview.sha256
```

必须测试权限、文件校验、损坏文件、快照哈希、路径安全、空结果和预览业务表零写入。

## 8. PR 2：正式导入

确认前校验data_admin、POST、批次状态、文件及预览哈希、schema和有效行。正式写入前生成：

```text
rollback_snapshot.json
rollback_snapshot.sha256
pre_import.sqlite3
```

`rollback_snapshot.json`按学生保存导入前Student、ApplicationRecord、Summary和有效Reports状态，并用`student_existed_before`区分本批新建学生。使用临时文件加原子重命名和SHA-256。

业务写入必须处于`transaction.atomic()`中；错误行不得改变旧数据，警告行可进入导入，原始总篇数不得被计算值覆盖，思想汇报保持真实sequence_number。重复确认、空预览确认和状态冲突返回409。

导入失败时业务写入全部撤销，但保留文件、批次、快照、备份和错误证据，并记录failed状态。

## 9. PR 3：最近批次回滚与备份

只允许data_admin通过POST回滚最新一次success、未回滚且没有后续成功批次的导入。回滚前校验JSON快照、SHA、schema、batch ID和当前数据归属。

已有学生按快照恢复；本批新建学生只有在来源批次、关联数据和后续变化检查全部安全时才删除。任一对象无法安全恢复则整批返回409并保持数据库不变，不允许部分回滚或自动改为inactive。

思想汇报恢复采用删除本批次明细并按快照重建原有效明细，不修改现有唯一约束，也不长期堆积多份inactive历史。

SQLite备份仅用于停机维护下的灾难恢复，不作为网页回滚数据源；恢复工具必须校验备份并在恢复前再次备份当前数据库。

## 10. 状态机

```text
previewed
├── 确认失败 → failed
└── 确认成功 → success
                  └── 回滚成功 → rolled_back
```

只有previewed可确认一次；只有最新success可回滚；失败回滚保持success；rolled_back不可重复回滚。

## 11. 合并顺序与门禁

```text
文档治理
→ 管理员模块
→ 上传与预览
→ 正式导入
→ 回滚与备份
→ 阶段集成与文档封板
```

每个PR必须基于最新develop，只修改任务范围文件，更新对应Module Notes及契约实现状态，并执行check、迁移检查、migrate、全量测试和`git diff --check`；最终SHA必须通过Repository policy、Ubuntu和Windows CI。
