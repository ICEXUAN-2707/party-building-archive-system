# 部署发布工程计划（V1.4）

## 1. 发布路径

```text
任务1：容器CI与固定IP HTTP候选收敛
  → 任务2：WorkBuddy服务器脱敏演练
  → 任务3：自购服务器正式部署
  → develop到main发布PR
  → RC Tag与正式发布审批
```

三个任务顺序执行。任务2和任务3使用同一Dockerfile、Compose结构和环境变量键名，但秘密、管理员账号、数据库、媒体和备份目标完全隔离。

## 2. 任务1：发布候选收敛

- 构建以候选SHA命名的Web镜像；
- 执行固定SHA的Trivy Action，阻断已有修复版本的CRITICAL漏洞；
- 在Runner临时目录建立数据库、媒体、静态和备份目录；
- 使用虚假生产配置启动Gunicorn单worker和Nginx；
- HTTP只绑定Runner回环端口；
- 验证健康端点、静态资源、8000未暴露和重启持久化；
- 统一固定公网IPv4 + HTTP的设置、Compose、Nginx、脚本、测试和文档；
- Ubuntu、Windows、Repository policy、容器合同与动态冒烟在同一SHA全绿。

完成后冻结候选SHA。CI不发布镜像、不连接服务器、不使用生产秘密。

## 3. 任务2：WorkBuddy服务器演练

- 确认Ubuntu版本、CPU、内存、磁盘、Docker、sudo、固定IPv4及80端口策略；
- 只使用合成数据和演练账号；
- 完成首次部署、迁移、九支部初始化、登录、查询、导入、回滚和审计抽查；
- 验证容器、Compose和宿主机重启后的数据持久化；
- 执行本机备份、COS上传、下载与隔离恢复；
- 演练应用升级和固定镜像回退；
- 记录镜像摘要、RPO、RTO、问题和修订项。

WorkBuddy服务器不得保存真实学生数据或长期生产凭据。

## 4. 任务3：自购服务器正式部署

- 登记服务器、固定公网IPv4、安全组、SSH来源、COS、责任人和授权；
- 22端口仅允许管理员来源，80端口仅允许校园网、VPN或明确可信来源；
- 部署任务2验证过的不可变镜像；
- 使用全新的生产秘密、管理员账号、数据库和备份目标；
- 先用合成数据验收，再在授权后导入真实数据；
- 启用健康、磁盘和备份告警；
- 完成恢复及回退证据并进行Go/No-Go签字。

若必须向不受信任公网开放，任务3阻断，必须先升级并评审HTTPS方案。

## 5. Go门禁

正式发布必须同时满足：

1. 任务1候选SHA全部CI通过；
2. WorkBuddy脱敏演练完成；
3. 自购服务器主机预检和网络隔离通过；
4. 备份、COS指定版本异机恢复及应用回退通过；
5. RPO不超过24小时、RTO不超过4小时；
6. 不存在未接受的P0/P1缺陷；
7. 项目、运维、数据和安全负责人签字。

任一项缺失时，不创建正式Tag、不导入真实数据、不开放访问。
