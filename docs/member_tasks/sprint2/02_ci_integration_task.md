# 任务卡：成员2 第二轮迭代持续集成与集成验收

## 任务目标

建立学生、管理员和Excel三条业务链的集成测试与发布门禁。

## 任务背景

现有模块测试通过，但Excel上传、确认和回滚仍未形成业务闭环；模块测试不能替代同一发布候选SHA上的端到端验收。

## 前置依赖

- 已冻结的`student_profile_contract.md`、`admin_query_contract.md`、`excel_import_contract.md`
- `import_rollback_contract.md`及JSON快照、哈希、冲突和恢复方案评审结论
- 成员4学生个人页候选
- 成员5管理员权限与查询候选
- 成员7导入候选

## 允许范围

- `.github/workflows/ci.yml`
- `scripts/ci_guard.py`
- `tests/`中的跨模块集成测试
- 发布测试报告

## 禁止范围

- 不修改业务规则或实现。
- 不降低检查强度以使PR通过。
- 不使用真实学生Excel文件或生产环境密钥。

## 接口契约

消费全部冻结契约；学生总篇数回退、管理员认证隔离、有效行局部导入、确认原子性和回滚冲突均以契约为准。发现不一致时报告提供方，不在测试中创建兼容逻辑。

## 实施建议

按匿名、学生、viewer_admin、data_admin四种身份建立矩阵；使用动态虚构Excel覆盖上传到查询和回滚的完整链路。测试只消费冻结接口，发现不一致时阻断候选并报告提供方。

## 必须测试

- 学生登录→本人页→退出。
- 管理员退出同时清除管理员认证和`student_id`；学生退出保留管理员认证。
- viewer_admin查询及导入历史/详情允许，上传、预览、确认、下载和回滚403。
- data_admin查询、上传、预览、确认、下载和回滚允许。
- 上传→服务端快照→预览零业务写入→确认→查询→审计。
- 确认校验原文件哈希、快照哈希、schema、批次ID和状态，不信任客户端重建结果。
- JSON快照方案评审通过后，测试最近一次成功批次回滚、快照缺失/损坏、schema或批次错误、后续变化冲突整批拒绝、事务失败撤销和证据保留。
- `makemigrations --check`证明没有新增快照模型或迁移，SQLite备份不能通过Web恢复。
- Ubuntu/Windows同一SHA。

## 验收标准

- 未授权入口均由后端拒绝。
- 三条业务链的状态、数据和权限断言明确。
- 导入和回滚断言覆盖实际数据库结果、批次状态、文件证据和审计，不只检查HTTP状态码。
- 最终候选没有数据库、上传文件或缓存污染。
