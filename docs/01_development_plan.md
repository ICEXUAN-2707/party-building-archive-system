# 学院学生材料信息查询系统开发执行计划 V1.0


# 1. 项目目标

本项目目标：

在约3-5周内完成一个接近正式上线标准的学院内部信息查询系统。

最终交付：

学生：

- 姓名+学号登录
- 查询本人材料信息

管理员：

- 查询全部学生
- 筛选查询
- 查看详情

数据管理员：

- Excel上传
- 数据预览
- 错误校验
- 正式导入
- 导入记录
- 最近一次回滚

部署：

- Docker化
- 校园内网运行
- 可迁移部署

- 测试记录

AI不是替代开发者。

- 提供方案

## Sprint 1：查询业务闭环
### 基础信息
- **周期**：Day4-Day12
- **Sprint目标**：完成学生查询、管理员查询全链路，产出系统首个可用Demo

### Sprint 1整体业务流程
#### 学生端流程
姓名 + 学号输入 → 身份校验匹配 → 跳转个人信息页
#### 管理员端流程
账号密码登录 → 展示全部学生列表 → 查看单名学生完整详情

- 负责人：成员3
- 开发分支：feature/student-auth
- 开发周期：Day4-Day8
#### 输入参数

#### 输出逻辑
- 校验成功：跳转个人信息页面
- 校验失败：统一弹窗错误提示
#### 开发内容
1. **后端**
   - 学生信息查询接口
   - 登录视图逻辑
   - Session会话管理
2. **前端**
   - 学生登录页面
3. **安全控制**
   - 接口越权访问拦截
#### 依赖数据模型
Student表
#### 前置依赖
Sprint 0 数据库模型开发完成
#### 验收测试用例
| 测试场景 | 预期结果 |
|---------|----------|
| 正确姓名+学号组合 | 登录成功，进入个人页 |
| 姓名学号不匹配 | 登录失败，弹出提示 |
| 输入空内容提交 | 登录失败，弹出提示 |
| 手动修改URL访问他人信息 | 拒绝访问，拦截跳转 |

## Sprint 2：Excel数据闭环
### 基础信息
- **周期**：Day13-Day24
- **Sprint目标**：完成Excel上传 → 解析 → 预览 → 数据库导入 → 数据查询更新完整数据流

### Task4 Excel解析模块
- 负责人：成员6
- 开发分支：feature/excel-parser
- 开发周期：Day13-Day20
#### 输入源
真实业务Excel文件（单文件1500条学生数据）
#### 输出数据结构
```python
students = []        # 学生实体列表
reports = []         # 思想汇报实体列表
warnings = []        # 数据警告集合
errors = []          # 数据错误集合
```
#### 支持能力
- 多Sheet表单解析
- 识别前两行作为表头
- 自动识别支部字段
- 标准化日期解析转换
- 自动统计第N次思想汇报
#### 验收标准
使用1500条真实Excel测试，页面输出统计：学生总数、错误条数、警告条数

### Task5 Excel导入模块
- 负责人：成员7
- 开发分支：feature/excel-import
- 开发周期：Day17-Day24
#### 关联页面编号
A-04、A-05、A-06、A-07
#### 业务流程
文件上传 → 数据预览校验 → 确认导入 → 更新数据库
#### 数据安全保障（强制实现）
1. 数据库事务回滚机制
2. 原始Excel文件本地持久保存
3. 完整导入操作日志记录
#### 验收测试场景
1. 正常场景：100条合规数据，完整导入数据库
2. 异常场景：支部名称错误、日期格式非法、重复学生数据，全部捕获并提示

### Sprint2 集成测试
- **时间**：Day24
- **核心校验**：大批量真实数据一致性
  1. Excel源文件：1500条记录
  2. 数据库入库：1500条无丢失
  3. 前端列表页面展示数据与数据库完全一致
