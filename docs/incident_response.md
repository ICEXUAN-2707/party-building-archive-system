# 故障响应手册（DEP-09）

## 1. 通用流程

先限制影响、暂停Excel导入和其他写入，记录时间、版本、健康状态及最近变更；保留脱敏日志和文件现场。P0数据损坏或泄露立即停机并通知项目、运维、数据和安全负责人。未经批准不得删除数据、重建主机、替换数据库或放宽安全门禁。

## 2. 容器不健康或502/503

观察`docker compose ... ps`、最近200行Web/Nginx日志、`/health/live/`和`/health/ready/`。检查数据库路径权限、磁盘、生产变量键是否齐全及Nginx到Web内部网络。禁止把8000临时开放公网。若新版本导致故障且迁移兼容，按运维手册回退上一镜像。

## 3. 磁盘不足

使用`df -h`、`du -x -h --max-depth=2 /srv/party-archive`和Docker磁盘统计定位。先暂停写入并通知负责人。只按已批准保留策略清理可再生缓存或过期、已验证的备份；不得删除当前数据库、原始Excel、最近五个导入批次、审计记录或唯一异机备份。

## 4. TLS临期或失效

确认域名、证书链、私钥权限和到期日。30天内到期告警，7天内升级为严重事件。更换后执行Nginx配置检查、平滑重启及浏览器受信任验证。禁止以关闭HTTPS或忽略证书警告作为正式修复。

## 5. 备份过期或COS失败

暂停正式导入，检查定时器、最近服务日志、COS最小权限、Bucket区域和时间同步。恢复上传后校验对象大小、SHA-256、加密头和版本ID。超过25小时没有成功异机备份时不得进行高风险变更。

## 6. SQLite损坏

立即停止Web及所有数据库访问进程，保留数据库、WAL/SHM及日志现场。禁止在线复制或直接覆盖。按`docs/backup_restore_guide.md`先只读验证备份，再在维护模式恢复；恢复失败保持停机并升级数据负责人。

## 7. 安全或隐私事件

撤销疑似泄露凭据，限制入口，保留审计证据并通知安全/隐私负责人。工单仅记录必要脱敏信息，不复制真实Excel、Cookie、Session、密码或完整学生资料。是否通知相关人员及监管方由授权负责人依据制度决定。
