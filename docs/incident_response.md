# 故障响应手册（DEP-09）

## 1. 通用流程

先限制影响、暂停Excel导入和其他写入，记录时间、版本、健康状态和最近变更；保留脱敏日志与文件现场。P0数据损坏或泄露时立即停机并通知项目、运维、数据和安全负责人。未经批准不得删除数据、重建主机、替换数据库或放宽安全门禁。

## 2. 容器不健康或502/503

检查 `docker compose ... ps`、最近200行Web/Nginx日志、`/health/live/` 和 `/health/ready/`。检查数据库路径权限、磁盘、生产变量和内部网络。禁止把8000临时开放到公网。若新版本导致故障且迁移兼容，回退上一固定镜像。

## 3. 磁盘不足

使用 `df -h`、`du -x -h --max-depth=2 /srv/party-archive` 和Docker磁盘统计定位。先暂停写入；只按批准的保留策略清理可再生缓存或已验证的过期备份。不得删除当前数据库、原始Excel、最近五个导入批次、审计记录或唯一异机备份。

## 4. HTTP入口暴露范围异常

若80端口被开放给未登记来源，立即通过云安全组和宿主机防火墙收窄来源，检查访问日志并通知安全负责人。不得以隐藏登录链接代替网络隔离。若业务必须面向不受信任公网，停止HTTP上线并升级到HTTPS方案。

## 5. 备份过期或COS失败

暂停正式导入，检查定时器、服务日志、COS最小权限、Bucket区域和时间同步。恢复上传后校验对象大小、SHA-256、加密头和版本ID。超过25小时没有成功异机备份时不得执行高风险变更。

## 6. SQLite损坏

立即停止Web和所有数据库访问进程，保留数据库、WAL/SHM及日志现场。禁止在线复制或直接覆盖。按 `docs/backup_restore_guide.md` 先只读验证备份，再在维护模式恢复；失败时保持停机并升级数据负责人。

## 7. 安全或隐私事件

撤销疑似泄露凭据，限制入口，保留审计证据并通知安全/隐私负责人。工单不得复制真实Excel、Cookie、Session、密码或完整学生资料。
